# 처방 용량 표시와 실제 처방량 입력 수정

기준 커밋: `461d8c2c2ff8b844b2c7883bd5aaa9f925e19f38` (`hanui-api-v13`).

## 변경된 동작

- 원본 참고량은 수치와 실제 단위로 표시한다. 수치가 없으면 원문 용량 메모를 표시하고, 메모도 없으면 `원본 용량 미등록`으로 표시한다. 누락량을 0 g로 만들거나 원문 메모에서 수치를 추정하지 않는다.
- 실제 처방량은 담당자가 별도의 수치·단위 입력란에 입력한다. 기업 원본 필드는 읽기 전용으로 보존한다.
- 작성·정정·저장 상세·데스크 인쇄에서 원본 참고량과 실제 처방량을 구분한다. 저장된 원본의 단위가 L/mL이면 그대로 표시한다.
- 저장 상담 복원 후 선택 병증이 있으면 처방 검색을 실행한다. 복원한 병증 결과를 보존하는 다른 입력 변경 방지 조건은 유지한다.
- 미평가 연결 처방도 상태를 표시하며 작성 화면에서 선택할 수 있다. 점수·순위를 임의로 부여하지 않는다.
- 작성 화면에서 상담을 직접 선택해 불러온 추천 결과의 병증 ID도 기업 자료 연결 조회에 사용한다.

## 요청·저장 계약

기존 약재 항목의 `amount`, `unit`, `preparation`, `originalDoseInfo`는 원본 참고 정보다. 기존 검증과 원본 변경 거부 정책을 유지한다.

선택 필드 `prescribedAmount: string | null`, `prescribedUnit: string | null`을 추가했다. 둘은 함께 입력하거나 함께 생략한다. 수치는 0보다 큰 십진수 문자열이며 지수·NaN·Infinity·음수는 거부한다. 임상적 용량 적합성은 이 형식 검사로 판단하지 않는다.

실제 처방량은 기존 `PATIENT_PRESP_VERSION.INGREDIENTS_JSON` 안에 저장되므로 테이블 변경은 필요 없다. 기존 저장·정정 API, 버전 이력, 전송된 버전 고정 정책을 사용한다. 실제 처방량을 생략한 이전 클라이언트 요청과 과거 저장본도 지원한다. 과거 데이터에 현재 원본 용량을 자동 덮어쓰지 않는다.

## 검증

백엔드:

```powershell
python -m unittest discover -s backend/tests -v
```

프런트엔드 (`frontend`에서):

```powershell
npm ci
npm test
npm run build
npm run test:browser
```

브라우저 검사는 Windows Edge를 기본 사용한다. 다른 Chromium 실행 파일은 `HANUI_TEST_BROWSER`에 지정한다. 전용 임시 프로필과 127.0.0.1:5181 테스트 서버를 사용하고 종료한다. API는 가상 자료로 대체하여 실제 서버나 DB에 요청하지 않는다. 테스트 페이지는 배포 빌드에 포함되지 않는다.

브라우저 검사 범위: 상담 복원→미평가 처방 선택, 저장 추천의 병증 ID 복원, 실제 처방량 제출, 기존 L/mL 표시, 실제 처방량 정정 요청, 데스크 저장본 인쇄.

PostgreSQL 통합 검사는 기존처럼 `HANUI_RUN_POSTGRES_TESTS=1`인 검증 환경에서 실행한다. 실제 처방량 저장→이전 버전 조회→정정→전송된 이전 버전 유지 시나리오를 추가했다. PostgreSQL 없이 실행하면 해당 검사들은 건너뛴다. 운영 DB를 대상으로 자동 실행하지 않는다.

## 적용 시 확인

백엔드와 프런트를 함께 배포하고 서버를 재시작해야 새 실제 처방량 필드를 사용할 수 있다. 기업 조회에는 기존과 같이 `KM_CDSS_CATALOG_ROOT`의 전체 JSONL과 동일 버전 `KM_CDSS_CATALOG_WORKBOOK`이 필요하다. AI 검색용 7개 파일만으로는 전체 기업 약재 구성을 조회할 수 없다.

이번 변경은 용량 입력·표시와 상담/처방 화면 연결을 다룬다. 검색의 키워드·문맥·부정 처리 정책은 변경하지 않는다.
