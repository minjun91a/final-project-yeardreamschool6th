`421c48b`는 이전 기준에서 `backend/catalog.py`의 파일 해시 계산을 Python 3.10 호환 방식으로 바꾼 커밋입니다. `c4e08c2`는 제출 자료 추가 커밋이며 서비스 구현의 새 성능 측정 기준이 아닙니다.

### 확인한 주요 조건

- 상담 저장 후 상태 보호와 권한·예외 처리
- 원본 참고량과 실제 처방량·단위의 저장·재조회 분리
- 선택 병증의 연결 처방 범위와 자료 부족 상태
- 증상 문맥의 검색 전달과 포함·제외 동작
- 설명의 원문 관계·인용 검사, 성공 캐시와 취소 처리
- 직원 초대·가입·승인 경로와 SMTP 실패·중복·권한 처리

실제 SMTP 테스트 1건은 메일 서버가 전송 요청을 수락한 `sent` 결과입니다. 받은편지함 도착이나 실제 수신자의 가입 완료로 확대하지 않습니다. [기존 SMTP 검사 조건](../staff-invitation-smtp.md)

## Elice CPU / GPU 비교

| 환경 | 조건 |
|---|---|
| GPU | NVIDIA A100 80GB 중 **MIG 1g.10gb 한 조각**, CUDA 표시 메모리 9,728 MiB |
| CPU / 메모리 | 2 vCore / 24 GiB |
| 모델 | Qwen3.5-4B Q4_K_M |
| 실행 | 같은 llama.cpp 실행 파일, CPU 모드와 GPU offload 모드 비교 |
| 고정 조건 | 스레드 2, 컨텍스트 4096, temperature 0, seed 42, 슬롯 1 |
| 대상 / 횟수 | 사전 고정 후보 3개, CPU·GPU에서 각 1회 |
| 유지한 처리 | 원본 관계 검사 → 생성 → 인용 일치 검사 → 별도 검토 → 검토 응답 검사 |

| 후보 ID | CPU 생성·검토 | GPU 생성·검토 | 결과 |
|---|---:|---:|---|
| 17693 | 303.513초 | 72.887초 | 양쪽 READY |
| 8355 | 272.138초 | 12.753초 | 양쪽 READY |
| 7415 | 308.073초 | 12.664초 | 양쪽 READY |
| 중앙값 | **303.513초** | **12.753초** | 약 **23.80배** |
| 순차 합계 | **883.724초** | **98.304초** | 약 **8.99배** |

첫 GPU 요청에는 추가 GPU 코드 준비 비용이 포함됐으며 72.887초를 제외하지 않았습니다. 각 후보 처리 전 애플리케이션의 완성 결과 캐시를 비웠고, 서버의 `cache_prompt=true`는 양쪽에서 유지했습니다.

별도 초기 준비 진단에서는 모델 준비 54.672초와 첫 검증된 설명 72.149초를 관찰했습니다. 모델 파일은 OS 캐시에 남아 있던 조건입니다. 서버를 요청마다 새로 띄우는 방식과 상주 상태의 처리 시간을 구분해야 합니다.

현재 수치에 포함하지 않은 것:

- DB 조회·E5 검색·인증·화면 렌더링을 합친 전체 응답
- 동시 접속, p95, 여러 번 반복한 통계
- 검색 정확도·문맥 분류의 독립 정답 평가
- 임상적 적합성·효과·안전성

전체 재현 명령·버전·해시·호환성 처리: [기존 GPU 검증 기록](../elice-gpu-benchmark.md)
