# 최민준의 기여

이 문서는 팀 전체 기능 소개와 개인 작업을 구분합니다. 서비스의 UI와 업무 API 전체를 단독 구현한 프로젝트가 아닙니다.

## 역할 구분

| 구분 | 주요 작업 |
|---|---|
| 최민준 중심 | 기업 데이터 정합성, 병증·처방 검색과 근거 연결, AI 입출력 계약, 설명 검증, 회귀 검사와 GPU 비교, 최종 산출물 정리 |
| 이상준 중심 | React 업무 화면, FastAPI 업무 API·DB 연동, 계정·접수·상담·처방 흐름, UI 개선과 시연영상 제작 |
| 공동 | 요구사항·상담 처리 순서 협의, 검색 API의 서비스 연결, 기능 통합과 오류 확인, 최종 발표 준비 |

## 1. 기업 자료를 추적 가능한 검색 입력으로 정리

- 병증·검색 키워드·처방 관계의 식별자, 중복과 참조 무결성을 확인했습니다.
- 파일 해시, 시트·행·셀 위치, 원문 구간과 청킹 정보를 검색 결과에 연결했습니다.
- 384차원 E5 임베딩 행렬과 원문 조각의 범위·내용을 대조했습니다.
- 원본에 없는 약재 구성은 임의로 보충하지 않고 누락 상태를 구분했습니다.

관련 코드: [`runtime.py`](../../backend/ai/runtime.py), [`load_search_data.py`](../../backend/scripts/load_search_data.py), [`catalog.py`](../../backend/catalog.py)

## 2. 증상에서 병증·연결 처방으로 이어지는 검색

- Kiwi 기반 표현 처리와 문맥 결과를 검색에 전달했습니다.
- 키워드 검색과 `multilingual-e5-small`의 의미 검색 순위를 RRF로 결합했습니다.
- 선택 병증의 실제 연결 관계로 처방 범위를 제한하고, 평가 불가 후보는 점수·순위와 분리했습니다.
- API의 후보·근거·설명 상태와 검색 이력 식별자를 구분해 팀원과 계약을 맞췄습니다.

관련 코드: [`ai/`](../../backend/ai/), [`ai_rrf.py`](../../backend/ai_rrf.py), [`ai_semantic.py`](../../backend/ai_semantic.py)

## 3. 생성 문장을 원문과 대조하는 단계 구성

후보와 출처의 관계를 확인한 뒤 Qwen에 설명을 요청합니다. 출력 형식·식별자·인용 원문 일치를 먼저 확인하고, 통과한 문장만 별도의 검토 호출에 전달합니다. 원문 밖 인용은 설명 미반환과 실패 사유로 처리합니다.

이 과정은 모델이 원문 밖의 문장을 그대로 사용자에게 내보내는 일을 줄이기 위한 구현입니다. 두 번째 모델 호출은 **별도 프롬프트 검토**이며 다른 독립 모델이나 임상 전문가의 검증을 뜻하지 않습니다.

관련 코드: [`explanations.py`](../../backend/ai/explanations.py), [`evidence_checks.py`](../../backend/ai/evidence_checks.py)

## 4. 팀원 UI와 범위를 나눠 통합 오류 개선

사용자가 작성한 실제 처방량과 단위의 저장·재조회, 저장된 상담을 구형 상태 변경 경로가 우회하는 문제, 증상 문맥 누락, 설명 대기 흐름을 점검했습니다. 변경을 백엔드와 데이터 표시 커밋으로 나눠 팀원 UI의 배치·스타일 작업과 분리했습니다.

[PR #3](https://github.com/sanjune2/km-cdss-project/pull/3)는 제안·검증 기록입니다. 해당 PR이 병합됐다는 의미로 인용하지 않습니다. 최종 반영 상태는 팀 통합 `main`의 코드와 [제출 기준 커밋](https://github.com/sanjune2/km-cdss-project/commit/c4e08c269d4e8a68451069e998bbb078b75f9874)으로 확인할 수 있습니다.

개선 사례는 [문제 해결 기록](engineering-notes.md)에 정리했습니다.

## 5. Elice 인스턴스에서 검증 절차를 유지한 GPU 비교

로컬 PC 대신 Elice A100 MIG 10GB·2 vCore·RAM 24 GiB를 기준으로 실행 환경을 준비했습니다. 같은 후보·모델·프롬프트·검증 함수를 사용해 CPU와 GPU를 비교하고, 첫 요청과 초기 준비 비용도 별도 기록했습니다.

GPU가 보이는지 확인하는 데서 끝내지 않고 실제 레이어 offload와 생성·인용·검토 결과를 확인했습니다. 당시 팀 웹서비스는 인스턴스에서 배포·연결되지 않았으므로 **서비스 전체 배포 완료나 전체 응답 성능을 주장하지 않습니다.**

관련 코드: [`backend/scripts/`](../../backend/scripts/) · [기존 GPU 검증 기록](../elice-gpu-benchmark.md)

## 6. 결과를 검토할 수 있는 자료로 남기기

요구사항·ERD·API·WBS, 팀 시연영상과 발표자료, 제출 전 재검사 조건을 정리했습니다. DB·모델·설정이 없는 공개 소스의 실행 조건과, 재검사에서 DB 검사가 생략된 범위를 제출 안내에 명시했습니다.

테스트 수나 처리 시간은 개발 검증의 범위에서만 사용하며, 독립 정답 평가와 임상 품질로 확대하지 않았습니다.
